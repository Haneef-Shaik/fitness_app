DS-6 was told not to edit app config, package files, theme or source outside its own store-art paths.
These are the changes that wire the generated art in. Apply them only after the art has been

```diff
-      dark: { backgroundColor: momentum.colors.dark.surface },

```

Notes:

- The prop names come from the installed `@expo/config-types` 57 (`icon`, `android.adaptiveIcon.{foregroundImage,
  monochromeImage, backgroundColor}`) and `expo-splash-screen` 57.0.10 `plugin/build/types.d.ts`
  (`image`, `imageWidth`, `resizeMode`, `dark.image`). They were read from the main checkout's
  `node_modules`, and they match this worktree's lockfile pins.
- `imageWidth: 200` shows the badge at about 107 dp, because the splash PNG keeps its content inside the
  inner two-thirds circle. At any `imageWidth`, the content stays inside the Android 12 icon mask if the
  plugin masks relative to the image box. That was not verified here. Judge the size and check for
  clipping on a release build.
- One splash PNG serves both themes. The lime badge is a large filled shape on both `#FEFCF4` and
  `#0E0F0A`, which docs/22 allows. Lime is never used as a thin line.
- The export gate (`expo export`) does not exercise icons. Prebuild and a release build (PL-7, PL-8)
  are the real proof.
