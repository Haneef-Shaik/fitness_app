## Findings

**1. Medium (blocks §6 only): the shared target is proved from the config, not from what listens at 55322**
- **Location:** `mb1-replay.mjs:234-240` (`sharedRunning`), `:588-593` (`stagedRunning`), `:242-250` (the fingerprint is only Running and StartedAt), `:630-632`.
- **The defect:** the claim "the CLI resolves to 55321 and 127.0.0.1:55322" rests on `supabase status`, and the container check is by name only. As far as I can tell, status builds its DB_URL from the config's `[db]` port. That is an inference: the Go binary has never been read (phase 1E). So the check passes whenever the config says 55322, whatever is actually published there. Snapshots read the named container through `docker exec`, while `migration up` writes over TCP to 127.0.0.1:55322. Nothing proves these are the same server.
- **Failure scenario:**
  1. Every fitlog worktree's config names `fitlog_rebuild_20261017`. Suppose the shared container was started from a worktree whose ports differ, and some other server answers on 55322.
  2. `55321-before` checks one database, and `migration up` writes another (every pending migration, if that one is empty or has drifted).
  3. The post-apply snapshot STOPs, but only after the write, and the apply is used up on this replay.

  This can't happen today: §6 isn't authorized, and its prerequisites are missing. No personal or health data is exposed.
- **Fix:** SF-7, below.

**2. Low: a failed M2 run can still be repeated, and a test asserts that it can**
- **Location:** `mb1-replay-order.mjs:72-76`, and `mb1-replay-order.test.mjs:66-81` (`:73` and `:80-81` assert the repeat is allowed).
- **The defect:** review 0305Z's low is still open in code. `suite m1` and `suite m3` have no one-shot rule either (`:76`), so on a future replay a NOT met could be rerun until it is met.
- **Failure scenario:** a later pass replaces an unexplained first result. This can't happen on this replay (see above).
- **Fix:** refuse `suite m1|m2|m3` once any entry for that mutation exists. Flip the test first (RED), and make the refusal durable with finding 3's provisional entry.

**3. Low: a failed state write loses the durable stop, and releases the lock**
- **Location:** `mb1-replay.mjs:743-746`, `:779-788`.
- **The defect:** I confirmed this by reading the code (0005Z L1 and 0205Z L1). It is wider than STOPs. If `mutate m2` succeeds but the write fails, the state says `active null` while the ban clause is gone, and the lock is released.
- **Failure scenario:** later commands run on a replay whose state misdescribes it. The `restored` snapshot rule catches it, but only after more commands have run.
- **Fix:** keep the lock on any failed state write after a child process has run, and write a provisional suite entry before each mutation suite.

**4. Low: `readState` accepts any `shared` string**
- **Location:** `mb1-replay.mjs:712`, with `:246` and `:251-254`.
- **The defect:** a failed `docker inspect` reads as `absent`. A hand-edited or corrupted `shared: "absent"` would therefore pass `sharedUnchanged` while the shared container is gone. `prepare` only ever writes `true <ISO time>`.
- **Fix:** refuse any other format in `readState`, with a test.

**5. Low: the CLI's own folders in the staged workdir are not pinned**
- **Location:** `mb1-replay-target.mjs:28` and `:396-401`.
- **The defect:** files under `shared-apply/supabase/.temp` and `.branches` pass the inventory with any content, and the CLI may read them when it resolves its target.
- **Failure scenario:** today this is covered only by the single-writer condition.
- **Fix:** allow only exact names before the apply (`_current_branch` must read `main`).

**Informational:**
- The replay's `supabase/.temp/cli-latest` reads `v2.122.0`. So an earlier CLI child process looked up the latest release over the network. Earlier "no network" statements apply to the agents, not to the CLI.
- The handoff's hash tables have 54 rows covering 61 paths. I can't map the coordinator's 55 to them from here. `final-0335Z.md` has no recorded hash yet; it is clean on the scans above.

**Bounds:** code, tests and MB-1 docs only. No database, CLI, Docker, network, runner or Supabase command, and the replay is not touched. The code must keep reading today's `state.json` and give today's answers. The `shared` fingerprint format does not change, so this replay stays usable.

   - Gate: the same 282 tests, by name, all pass; `node --check` passes on every file; the 11 phase 1I patches are regenerated for the new layout, pass `git apply --check`, and are each still killed; hashes are taken before and after.
2. **SF-7, the shared-target binding (first priority).**
   - **(a) Docker's own binding.** Parse `docker inspect` labels and ports with a pure, fail-closed function:
     - the database container must carry the CLI project label (`com.supabase.cli.project`, to be confirmed on the first live read) equal to `fitlog_rebuild_20261017`, and publish `5432/tcp` only at host port 55322, on loopback or wildcard;

     - Call it in `sharedRunning`, again after `stagedRunning`, and after `migration up` as a STOP.
     - Docker's output shape is an assumption. After F5, anything unexpected refuses, and the first live read needs its own read-only authorization.
   - **(b) A proof over the same route `migration up` uses.** Before `guardsBeforeMigrate`, run `migration list --local --workdir <staged>` through the existing `migrationListResult`. It must show 16 local versions, exactly the 15 base versions remote, and the candidate local only. Anything else refuses before the attempt is recorded. That catches the replay (16 remote), an empty database or a drifted one.
   - **(c)** Finding 4's format check. **(d)** Finding 5's allowlist, if small; otherwise it moves to SF-3.
3. **Durable stops and refusals (second priority).**

   - SF-4: raise the runner's suite spacing from 75 s to 90 s, to match the gate.
4. **SF-5, exact pins.** Pin the exact sha256 of the four generated SQL files. For m2 and m3, the new `fn_definition_md5` must differ from `after` and from every other mutation snapshot. Today that check is done by hand.
