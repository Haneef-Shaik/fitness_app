**What I built:**
- **`.github/workflows/backend-ci.yml`**, with one job called `backend`. On a fresh runner it starts the local Supabase stack, which replays every migration. It then checks the replay, a schema diff and a schema lint, and runs `pnpm backend:test` as one plain step. I put it in its own file because QA-9 pins the layout of `mobile-ci.yml`.
- **`scripts/ci/backend-ci.mjs`**, a helper with six commands:
  - `base` checks that `FITLOG_BASE_REF` and `FITLOG_CONTRACT_BASELINE` are both the event's own base commit, the same commit, and full SHAs.
  - `local-main` fixes AR-1 L1 without editing another lane's test. It creates a local `main` at that base only when one is missing.
  - `vendored` covers QA-9 R6: Git may track no `node_modules` path.
  - `replay`, `diff` and `lint` decide from the Supabase CLI's JSON summary, not its exit code. The CLI exits 0 even when the diff isn't empty.
- **`scripts/ci/workflow-guard.mjs`** pins the new workflow's shape, so skipping a step, ignoring a failure, moving the base or unpinning an action breaks a test. It runs inside the job.
