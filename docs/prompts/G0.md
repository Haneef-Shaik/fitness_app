## How, in this repo

### Persistence — the constraint decides it

| Option | Transactions | Works in Expo Go? | Verdict |
|--------|-------------|-------------------|---------|
| `AsyncStorage` | ✗ key-value, no atomic multi-write | ✓ | **No** — an outbox needs atomic dequeue |
| `react-native-mmkv` | ✗ key-value | **✗ native module → needs a dev build** | **No** — DR4 says Expo Go |
| **`expo-sqlite`** | ✓ real transactions, queryable, WAL | ✓ ships in the Expo runtime | **Recommended** |

**Check `expo-sqlite` is available in the installed SDK before you write the decision down.** The
app is on Expo SDK 52 (`apps/mobile/package.json`). Verify, then note in D14 *how* you verified:

```bash
cd /Users/Adya/personals/fitness_app/apps/mobile
npx expo install --check expo-sqlite   # or inspect the SDK 52 bundled-module list
```

Recording a package as a decision without checking it exists is exactly the
`local_date`-generated-column mistake repeated — that one cost a schema task and everything
downstream of it.

Then put this in **§5.3**, with the reasoning, not just the SQL:

```sql
-- session_draft: exactly one row; the whole draft as JSON, rewritten per committed change
CREATE TABLE session_draft (id INTEGER PRIMARY KEY CHECK (id = 1),
                            revision INTEGER NOT NULL, updated_at TEXT NOT NULL, json TEXT NOT NULL);
-- outbox: one row per pending write, ordered, idempotent on client_id
CREATE TABLE outbox (id INTEGER PRIMARY KEY AUTOINCREMENT,
                     aggregate_id TEXT NOT NULL, method TEXT NOT NULL, path TEXT NOT NULL,
                     body TEXT NOT NULL, idempotency_key TEXT NOT NULL UNIQUE,
                     attempts INTEGER NOT NULL DEFAULT 0, next_attempt_at TEXT NOT NULL,
                     state TEXT NOT NULL DEFAULT 'pending', last_error TEXT);
CREATE INDEX ix_outbox_ready ON outbox (aggregate_id, id) WHERE state = 'pending';
```

**The asymmetry is the design and it belongs in the doc:** the draft is one JSON blob because it is
read and written **whole**; the outbox is rows because it is dequeued **in order and partially**.

### E2E runner

**Maestro** — YAML flows, drives Expo Go over the LAN, no native toolchain. Detox and Playwright
both require a build this machine cannot produce. Record that reasoning in D15, not just the name.

### Performance budget — replace web metrics with what a phone can answer

| Metric | Budget | Measured by |
|--------|--------|-------------|
| **tap → set rendered (p95)** | **< 100 ms** | `performance.now()` around the reducer + a post-commit frame callback, logged in dev builds |
| cold start → dashboard interactive | < 2.5 s mid-tier Android | manual stopwatch + `expo-router` mount log |
| JS bundle | tracked, not capped yet | `npx expo export` output size |

LCP, INP, gzip bundle size and Server Components are not measurable on a phone. The one budget that
survives the platform change is **tap → set rendered < 100 ms** — keep it.

as the real phone cases: **iOS purging app storage under pressure** and **Android "Clear data"**.
Both produce the same product behaviour — the draft is gone; say so plainly and start clean. Check
**O2** and **O12** the same way.
