## Your task

The API has **43 operations and 133 tests**. The mobile app has **no** server-state library, **no**
client store, **no** generated types, and `"test": "echo \"no mobile tests yet\""`. The house rule is
TDD with an 80% floor; the client is at **0%**.

## Standing rules

- **TDD.** Test first (RED), implement (GREEN), refactor. A test that has never failed has proven
  nothing.
- **Mutation-check every guard you add.** Break the implementation deliberately; a *named* test must
  fail. A guard whose removal breaks nothing is not a guard.
- **Assert every mutating call.** A test that calls an endpoint without checking its status can pass
  while the endpoint 500s. That is not hypothetical here — it happened, and it made an AC-12 test
  pass while proving nothing.
- **Verify, don't assert.** Run it against the live API, not "should work".
- **No cloud.** Every deliverable is a local file in this repo.

## How, in this repo

### Types — generated, never hand-written

`openapi-typescript` against the running server, output **checked in**. The gate mirrors the habit
already in this repo (`alembic check`, the cross-language contract job):

```yaml
- name: API types are in sync
  run: |
    uv run uvicorn app.main:app --port 8000 & sleep 4
    pnpm dlx openapi-typescript http://localhost:8000/v1/openapi.json -o packages/api-types/schema.d.ts
    git diff --exit-code packages/api-types/schema.d.ts   # a stale type is a failed build
```

With 43 operations, hand-typing is no longer an honest option. The OpenAPI document is at
`http://localhost:8000/v1/openapi.json` (`services/api/app/main.py`).

**You must see this gate fail.** Delete a field from a Pydantic schema in
`services/api/app/schemas/`, run the job, watch it fail, put the field back. A gate nobody has seen
fail is a gate nobody knows works.

### Query keys — one registry, so invalidation is greppable rather than guessed

```ts
export const qk = {
  activeSession:        ()               => ['session', 'active'] as const,
  session:              (id: string)     => ['session', id] as const,
  previousPerformance:  (exId: string)   => ['previous-performance', exId] as const,
  records:              (exId: string)   => ['records', exId] as const,
  exercises:            (f: Filters)     => ['exercises', f] as const,
  programs:             ()               => ['programs'] as const,
} as const;
```

Write the **invalidation map** as a table in `docs/03` §6.2 **first**, then implement against it —
not the other way round. For example: `finish session → [activeSession, session(id), records(*),
history]`. Every cached read gets one key and one documented invalidator.

### `DataBoundary` — four states, in one component

Loading · empty · **filtered-empty** · error. **Filtered-empty is not empty** (**I13**): different
copy, different action — "No exercises match *chest + barbell*. Clear filters." is not "You haven't
added any exercises yet." That distinction is a rule in the design system and a common bug
elsewhere; putting it in one component is how it stays true across the 97 remaining screens.

### Tests — start where silence is most dangerous

The server has 133 tests and the client has none. Begin with the pieces that are pure and already
exist in `apps/mobile/src/lib/api.ts`:

- envelope unwrapping → `ApiError` with `code`, `status`, `fields`, `request_id`
- the 401 → refresh → retry path, including refresh *failure* clearing the token
- LAN host derivation from `Constants.expoConfig.hostUri` (web vs device vs `EXPO_PUBLIC_API_URL`)

These are the code most likely to break silently. Then `DataBoundary`, one test per state.

Replace the placeholder script in `apps/mobile/package.json`:

```json
"test": "jest --coverage"
```

and add a CI job beside the existing three in `.github/workflows/ci.yml`.

  implemented from there.

## Traps — written before you hit them

- Generating types and then hand-writing "nicer" ones beside them. There must be **one** source. A
  hand-written type that shadows a generated one is drift with extra steps.
- A coverage gate set to today's number and never raised. Record the number **and** the intent.
- Migrating all six existing screens. Migrate **one**. Prove the spine, then move — a wide migration
  hides whether the substrate is actually good.
- Writing the invalidation map after the code. Then it documents what you did, not what is correct.
- Testing `DataBoundary` with three states because filtered-empty "is basically empty". It is not.
