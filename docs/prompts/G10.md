## Your task

The product becomes **observable, accessible, fast on a mid-tier Android, and exportable** — a user
can take their data and leave.

All twelve acceptance criteria are already proven when this starts. This goal is about everything
that is true of a product but not of a feature.

## Standing rules

- **Evidence, not assertion.** Every NFR gets a number or a recording, not an opinion.
- **The a11y pass is not a lint run.** It is you, using the app, with a screen reader on.
- **Mutation-check every guard.** Break it deliberately; a named test must fail.
- **No cloud.** Every deliverable is a local file in this repo.

## Scope — do exactly this

1. **Offline outbox end-to-end** + **L-02 sync centre** + **L-07 conflict**.
2. **RED metrics** and the alert table from [`docs/02`](../02-SYSTEM-ARCHITECTURE.md) §9, wired.
3. **Accessibility audit** — keyboard-only logging and a screen-reader pass on the diary and logger.
4. **Performance budgets measured on a mid-tier Android.**
5. **Account export and deletion, end-to-end.**

## How, in this repo

### The a11y pass is a thing you do

**Log a full session with a screen reader on.** **Navigate the diary with an external keyboard.**
An automated scan finds missing labels; it does not find that the set logger's focus order sends you
back to the top after every commit, or that the only indication a set synced is a colour.

Findings are **fixed, or logged with a date**. "Noted" is not an outcome.

### Observability

RED (rate, errors, duration) per endpoint, and the alert table wired. Then **deliberately trigger
one alert** and watch it fire. An alert nobody has seen fire is a configuration file.

### Performance

Measure the budgets from `docs/03` §9 on a **mid-tier Android**, not the newest device available:

- tap → set rendered p95 **< 100 ms** (compare against G4's number — regression here is a release
  blocker)
- cold start → dashboard interactive **< 2.5 s**
- JS bundle size, tracked

### Export and delete

This is a legal surface as much as a feature.

- Export produces a **complete** archive — every domain, in a documented format.
- **Deletion must remove the analysis rows from G8 too**, and the test must assert it. The append-only
  tables are the ones most likely to be forgotten, precisely because nothing else ever deletes from
  them.
- Assert that **nothing is left behind**: query every table for the user's id after deletion.

### The sync centre

L-02 makes the outbox visible: what is pending, what failed, what a user can do about it. L-07 is
the conflict surface. Both read the existing outbox (H3.2); neither invents new sync behaviour.

## Invariants you must not break

All fifteen — this is the goal that certifies them. In particular:

- **I11 — a regression is never red**, and **colour never carries meaning alone**: both get checked
  on the built app here, in both themes.
- **I12 — estimated never looks like confirmed** — verified visually, with a screen reader, where
  "dashed border" conveys nothing at all.
- **I14 — no AI failure touches training** — re-run G8's containment test as a release check.
- **I15 — each fact has one canonical home.** Closing the project's docs is part of shipping it.

## Traps — written before you hit them

- **An a11y audit that is an automated scan.** It will pass and the app will still be unusable with
  VoiceOver.
- **Deleting the user but not the analyses.** The append-only tables have no delete path by design —
  that is exactly why they get missed.
- Measuring performance on the fastest device in the house.
- An alert table committed but never triggered.
- Treating the accumulated "left undone" list as optional. It is the debt this project deliberately
  kept visible so that this goal could pay it.
