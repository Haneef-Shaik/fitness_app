## Standing rules

- **TDD.** Test first (RED), implement (GREEN), refactor.
- **Mutation-check every guard.** Break it deliberately; a named test must fail.
- **Assert every mutating call** — status *and* payload. A test that calls an endpoint without
  checking its status can pass while the endpoint 500s. That happened on this project and made an
  AC-12 test pass while proving nothing.
- **Verify, don't assert.** Run the screens against the live API.
- **No cloud.** Every deliverable is a local file in this repo.

## Scope — do exactly this

**Server pre-step (Finding 2), then eight screens** — [TODO §5](../TODO.md):

1. **`GET /exercises/{id}/history`** — that exercise's completed sessions with their sets.
2. **`GET /exercises/{id}/stats`** — the four records plus an e1RM series.
3. **D-01** exercise library — search, muscle/equipment filters, virtualised list.
4. **D-02** exercise detail — PRs, e1RM trend, recent sessions, **never-performed** state.
5. **D-03** custom exercise — the primary-muscle requirement enforced **in the UI**, not only the API.
6. **C-02 / C-03** programs list and detail.
7. **C-05** plan day editor — reorder, live set-count-per-muscle summary.
8. **C-06** exercise picker sheet — multi-select, "create from query" when the search is empty.
9. **C-07** prescription editor — **fields driven by the exercise's tracked fields**.

## How, in this repo

### The two endpoints first

Both are read-only aggregations over tables that already exist. Build them with the **same envelope**
(`app/api/envelope.py`), the **same `authorize()` policy call**, and the **same "assert every
mutating call" test discipline** as `sessions.py`. Integration tests assert **status and payload**,
not status alone.

### Tracked fields — the contract the logger inherits

`Exercise` already carries `tracks_load` / `tracks_reps` / `tracks_duration` / `tracks_distance`.
**C-07 must render from those flags**, not from a hardcoded load+reps form. A plank has no load; a
run has no reps. Getting this right here is what stops E-03 in G3 needing a special case per
exercise type — and a bug here surfaces as a *logger* bug there, where it is far more costly.

### Reuse — build C-06 as a standalone sheet

```ts
<ExercisePicker selected={ids} onChange={setIds} allowCreate />
```

G3 needs exactly this for **add exercise** and **swap exercise** mid-session. The selection state is
**controlled by the caller**, not owned by the screen. Building it screen-local here means building
it twice.

### Lists

`FlashList` or `FlatList` with a stable `keyExtractor` and a fixed row height. The catalog is 29
seeded exercises today and unbounded once users add their own.

## Invariants you must not break

- **I1 — the plan tree is not the performed tree.** Editing a program never changes a logged
  session. `target_snapshot` guarantees it server-side; nothing in the plan editor may reach into
  session rows.
- **I3 — warm-ups are excluded from volume and PRs** (D6). `/stats` must honour this.
- **I4 — muscle volume: primary ×1.0, secondary ×0.5** (D7). C-05's live set-count summary uses the
  same weighting as everything else.
- **I5 — Epley, stored as `epley_v1`.** `/stats`' e1RM series carries the version with the value.
- **I6 — canonical units in storage**; convert only at the display edge.
- **I13 — filtered-empty ≠ genuinely empty.** The catalog is where a user meets this first.

## Traps — written before you hit them

- **Hardcoding load+reps in C-07.** It will surface as a logger bug in G3, where it costs far more.
- **Skipping D-02's never-performed state.** It is the state a *new user* sees for *every* exercise
  — the most-viewed state in the screen, and the easiest to forget.
- **Letting the picker keep its own selection state.** The logger needs it controlled.
- Re-deriving records or e1RM in a SQL aggregate for `/stats` instead of using
  `app/domain/training.py`. A second definition is how AC-06 fails later.
- Building the list without a stable `keyExtractor` — it works at 29 rows and stutters at 300.
