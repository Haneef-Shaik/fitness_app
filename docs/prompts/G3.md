## Your task

A user starts a workout, logs every set **one-handed with the network off**, kills the app
mid-session, relaunches, resumes, finishes — and the server ends up holding **exactly** what the
phone showed, **with no duplicates**.

Everything before this goal was substrate. This is the thing the product is for. **AC-02 and AC-04
become reachable.**

## Standing rules

- **TDD, and reducers before UI.** The correctness lives in pure functions; test them before
  anything renders.
- **Mutation-check every guard.** Break it deliberately; a named test must fail. A guard whose
  removal breaks nothing is not a guard.
- **Assert every mutating call.** A test that calls an endpoint without checking its status can pass
  while the endpoint 500s. That is not hypothetical here — it happened, and it made an AC-12 test
  pass while proving nothing.
- **Verify, don't assert.** Airplane mode is a thing you *do*, not a thing you reason about.
- **No cloud.** Every deliverable is a local file in this repo.

## How, in this repo

### Reducers before UI

The store is where correctness lives and it is **pure**, so it is testable without rendering
anything. Write these tests **first**:

- append set · edit set · **delete set and re-densify** · reorder exercises
- prefill the next set from the last · **merge a recovered draft**

The server's `densify_set_indices` already exists as the reference. **The client must agree with
it** — test the same scenarios against both and compare.

### The commit path is the product — and it is non-negotiable

From `docs/03` §5.2:

```
tap ✓ → validate locally (@volt/domain setValidity)   ~0 ms
      → reducer returns a NEW draft, UI updates        ~0 ms   ← the user is already done
      → write draft to SQLite                          ~2 ms
      → enqueue POST /session-exercises/:id/sets with Idempotency-Key = set.clientId
      → start rest timer, prefill the next set
                    └── background: flush → 200 synced │ 5xx/offline retry │ 4xx failed, inline
```

**The UI never awaits the network** (**I10**). The only visible difference between online and
offline is the per-set sync dot.

### Idempotency — already guaranteed server-side

`uq_set_client_id` exists, and a replay returns **200 with the same row id** rather than 201. The
client's entire contract is: **generate `clientId` once, at commit, and never regenerate it on
retry.** Write a test that a replayed flush produces **one** row.

### Recovery — deterministic, from this table

On launch, read the local draft **and** `GET /workout-sessions/active`:

| Local | Server | Action |
|-------|--------|--------|
| none | none | normal start |
| draft | none | E-10 → Resume / Finish / Discard |
| none | active | adopt the server session |
| both, same id | — | **replay the outbox**; sets are idempotent, so replay is safe |
| both, different id | — | the one with **more sets** wins; the other is offered as discard |
| draft > 24 h old | — | prompt before resuming |

Every row gets a test.

### Finish

E-08 renders **from the draft**, client-side, so it is instant — then reconciles with the server's
`/finish` response. The server computes volume, e1RM and PRs **inside the finish transaction**, so
the numbers agree by construction: both sides come from `contracts/vectors/domain.json`.

### E-11 waits

The PR celebration appears **after** the summary. Interrupting someone mid-set to congratulate them
is the worst thing this screen could do.

### Rest timer

Counts from a **target timestamp**, not a decrementing counter. Backgrounding freezes timers; a
target instant survives it.

## Invariants you must not break

- **I10 — the set-commit path never awaits the network.** This goal is where the invariant is born;
  G4 measures it.
- **I8 — every write is idempotent on a client-generated key.** `clientId` is generated once.
- **I1 — the plan tree is not the performed tree.** `target_snapshot` froze the prescription at
  start; the logger writes performed rows and never reaches back into the plan.
- **I3 — warm-ups excluded from volume and PRs** (D6) · **I5 — Epley as `epley_v1`** ·
  **I4 — primary ×1.0, secondary ×0.5** (D7): the client's instant summary must use
  `@volt/domain`, never a local re-derivation.
- **I6 — canonical units in storage.** `load_unit_entered` records what the user typed; storage is kg.
- **I7 — the day is the profile's day.** The client never computes its own "today".
- **I9 — one envelope, always, with a `request_id`**, including the outbox's error surfacing.

## Traps — written before you hit them

- **Awaiting the POST "just for the first set".** Once the commit path *can* await, it will.
- **Regenerating `clientId` on retry.** This silently defeats every idempotency guard in the system
  — and it will look like it works, because the sets all appear. Twice.
- **Persisting on an interval instead of per commit.** The crash you are protecting against happens
  *between* intervals.
- **Building the outbox inside the session feature.** G7 (meals) and G9 (body metrics) need it
  unchanged — it goes in `src/lib/offline`.
- **Treating the rest timer as a counter.** Backgrounding freezes timers; store the target instant.
- Testing densify only through the UI. It is pure; test it directly and against the server's.
- A terminal 4xx swallowed into a log line. If a write can never succeed, the user must see it on
  the set it belongs to.
