## How, in this repo

### The flows

Maestro flows in `apps/mobile/.maestro/`, **one file per AC, named for the AC** (`ac-01-build-chest-
workout.yaml`, etc.) so a failure names the criterion it broke. Seed with
`cd services/api && uv run python scripts/seed_demo.py` so every flow starts from a known state.

**Assert against the API as well as the UI.** After the flow writes, query the endpoint and check
the rows: set count, dense `set_index`, the loads and reps that were entered. A green flow that only
read its own screen proves the screen, not the product.

### The measurement

Instrument the commit path behind `__DEV__`: `performance.now()` around the reducer plus a
post-commit frame callback, exactly as `docs/03` §9 specifies. Log **100 commits**, take the 95th.
Record the number, the device, and the conditions.

Budget is **< 100 ms**. If it misses, write down the number and open it as a tracker item — do not
quietly re-scope the budget, and do not declare it "fine" without the number.

### DR4 — the physical device

Expo Go on a real phone, on the same LAN as the API. Run the API on `0.0.0.0` so the phone can
reach it:

```bash
cd services/api && uv run uvicorn app.main:app --host 0.0.0.0 --port 8000
```

Confirm `defaultBase()`'s `hostUri` derivation actually resolves to the laptop's LAN IP. That code
path has never run on hardware; if it is wrong, this is where you find out and fix it.

## Invariants you must not break

- **I10 — the set-commit path never awaits the network.** Your instrumentation must not introduce an
  await into it. Measure around the reducer, not by wrapping the flush.
- **I8 — idempotency on a client-generated key.** The offline flow is the strongest test of this in
  the project; assert row counts, not just success.
- **I7 — the day is the profile's day.** Seeded data and assertions use the profile timezone.

## Traps — written before you hit them

- **Asserting only what the UI shows.** The UI is the thing most likely to be right; the write is
  the thing most likely to be missing.
- **Running the flows only on web**, where offline behaves differently and the keyboard does not
  exist. Web is for iteration; the proof is on the device.
- **Declaring the p95 "fine" without the number.** Every unmeasured budget on this project has
  eventually been wrong.
- Seeding by hand and then wondering why the flow is flaky. Use `seed_demo.py`; it is idempotent.
- Marking an AC proven because its flow is green, when the flow asserts a weaker statement than the
  criterion. Re-read `07-TRACEABILITY.md` §2 and compare word by word.
