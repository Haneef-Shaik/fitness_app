## How, in this repo

### One aggregated call

`GET /dashboard` returns training, nutrition and body state for **one local date**. The **local date
is resolved once, server-side, from the profile timezone**. The client **must not compute its own
"today"** (**I7**) — a phone in a different timezone from the profile is not a bug the client gets
to have an opinion about.

Measure B-01's request count **before and after** and put both numbers in the tracker. "It feels
faster" is not the standard this project uses.

### Q5 is already answered

**The first weigh-in of the day is canonical.** Later entries that day are recorded but do not
replace it. Implement that; do not re-open it.

### Goals

Reuse the existing `FitnessGoal` model from M1. This is a screens goal on top of an API that already
exists — resist the urge to redesign the model because the screens are new.

### Body metrics are offline writes

They go through **H3.2**, unchanged. Third domain on the same queue; if it does not fit, that is a
defect in the outbox's interface to fix, not a reason for a third queue.

### Empty domains render empty states

A user with no meals logged has a dashboard, not a 404. Each domain's section uses `DataBoundary`'s
empty state independently — one empty domain never blanks the other two.

## Invariants you must not break

- **I7 — the day is the profile's day.** This goal is where breaking it would be most visible and
  most tempting.
- **I2 — only `confirmed = true` nutrition counts** (D5). The dashboard is the place an unconfirmed
  estimate would most plausibly sneak into a total.
- **I12 — estimated never looks like confirmed**, and adds nothing to a total.
- **I6 — canonical units in storage** (kg, cm); convert at the display edge.
- **I8 — idempotency on a client-generated key**, body metrics included.
- **I13 — filtered-empty ≠ genuinely empty.**

## Traps — written before you hit them

- **Computing "today" on the device.** It will be right for almost every user and wrong for exactly
  the ones who travel — and it fails silently.
- **A dashboard that 404s when a domain is empty** instead of rendering its empty state. A brand-new
  user has three empty domains; that is the *first* dashboard anyone sees.
- Rebuilding `FitnessGoal` because the screens are new.
- Letting an unconfirmed meal item into the dashboard's macro ring "because it is just a preview".
- Replacing the fan-out without measuring it, so nobody can say whether it helped.
